# `rum.errors`

## Classes

### `ApplicationCommandError`

```python
class ApplicationCommandError(...)
```

The base exception type for all application command related errors.

This inherits from `DiscordException`.

This exception and exceptions inherited from it are handled in a special way as they are caught and passed into a special event from `.Bot`, `.on_command_error`.

### `ApplicationCommandInvokeError`

```python
class ApplicationCommandInvokeError(e: Exception) -> None
```

Exception raised when the command being invoked raised an exception.

This inherits from `ApplicationCommandError`

#### Attributes

original: `Exception`  
The original exception that was raised. You can also get this via the `__cause__` attribute.

### `CheckFailure`

```python
class CheckFailure(...)
```

Exception raised when the predicates in `.Command.checks` have failed.

This inherits from `ApplicationCommandError`

### `ClientException`

```python
class ClientException(...)
```

Exception that's raised when an operation in the `Client` fails.

These are usually for exceptions that happened due to user input.

### `ConnectionClosed`

```python
class ConnectionClosed(socket: Any, *, shard_id: int | None, code: int | None = None)
```

Exception that's raised when the gateway connection is closed for reasons that could not be handled internally.

#### Attributes

code: `int`  
The close code of the websocket.

reason: `str`  
The reason provided for the closure.

shard_id: `int` | `None`  
The shard ID that got closed if applicable.

### `DiscordException`

```python
class DiscordException(...)
```

Base exception class for rum

Ideally speaking, this could be caught to handle any exceptions raised from this library.

### `DiscordServerError`

```python
class DiscordServerError(response: _ResponseType, message: str | dict[str, Any] | None)
```

Exception that's raised for when a 500 range status code occurs.

Subclass of `HTTPException`.

*Added in 1.5.*

### `ExtensionAlreadyLoaded`

```python
class ExtensionAlreadyLoaded(name: str) -> None
```

An exception raised when an extension has already been loaded.

This inherits from `ExtensionError`

### `ExtensionError`

```python
class ExtensionError(message: str | None = None, *args: Any, name: str) -> None
```

Base exception for extension related errors.

This inherits from `discord.DiscordException`.

#### Attributes

name: `str`  
The extension that had an error.

### `ExtensionFailed`

```python
class ExtensionFailed(name: str, original: Exception) -> None
```

An exception raised when an extension failed to load during execution of the module or `setup` entry point.

This inherits from `ExtensionError`

#### Attributes

name: `str`  
The extension that had the error.

original: `Exception`  
The original exception that was raised. You can also get this via the `__cause__` attribute.

### `ExtensionNotFound`

```python
class ExtensionNotFound(name: str) -> None
```

An exception raised when an extension is not found.

This inherits from `ExtensionError`

*Changed in 1.3 Made the `original` attribute always None.*

#### Attributes

name: `str`  
The extension that had the error.

### `ExtensionNotLoaded`

```python
class ExtensionNotLoaded(name: str) -> None
```

This inherits from `ExtensionError`

### `GatewayNotFound`

### `HTTPException`

```python
class HTTPException(response: _ResponseType, message: str | dict[str, Any] | None)
```

Exception that's raised when an HTTP request operation fails.

#### Attributes

response: Any  
The response of the failed HTTP request.

text: `str`  
The text of the error. Could be an empty string.

status: `int`  
The status code of the HTTP request.

code: `int`  
The Discord specific error code for the failure.

### `InteractionResponded`

```python
class InteractionResponded(interaction: Interaction)
```

Exception that's raised when sending another interaction response using `InteractionResponse` when one has already been done before.

An interaction can only respond once.

*Added in 2.0.*

#### Attributes

interaction: `Interaction`  
The interaction that's already been responded to.

### `InvalidArgument`

```python
class InvalidArgument(...)
```

Exception that's raised when an argument to a function is invalid some way (e.g. wrong value or wrong type).

This could be considered the parallel of `ValueError` and `TypeError` except inherited from `ClientException` and thus `DiscordException`.

### `InvalidData`

### `LoginFailure`

### `PrivilegedIntentsRequired`

```python
class PrivilegedIntentsRequired(shard_id: int | None)
```

Exception that's raised when the gateway is requesting privileged intents, but they're not ticked in the developer page yet.

Go to <https://discord.com/developers/applications/> and enable the intents that are required. Currently, these are as follows:

- `Intents.members`
- `Intents.presences`
- `Intents.message_content`

#### Attributes

shard_id: `int` | `None`  
The shard ID that got closed if applicable.
